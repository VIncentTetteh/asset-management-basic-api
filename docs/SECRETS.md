# Secrets Inventory & Rotation

All secrets are supplied via environment variables (locally through an untracked `.env`; in deployment through the platform's secret store). **No secret value may ever appear in a tracked file — including `.env.example`, docs, test fixtures, or logs.** CI runs gitleaks to enforce this.

## Inventory

| Variable | Used by | Source / where to rotate | Notes |
|---|---|---|---|
| `APP_JWT_SECRET` | Backend auth (jjwt) | Generate locally: `openssl rand -base64 64` | ≥64 bytes. Rotating invalidates **all** issued access/refresh tokens (forced re-login). `StartupSecurityValidator` rejects weak values at boot. |
| `SPRING_DATASOURCE_PASSWORD` | Backend ↔ PostgreSQL | DB admin / RDS console | Rotate with a maintenance window. |
| `REDIS_PASSWORD` | Backend ↔ Redis | Redis config / ElastiCache | |
| `PAYSTACK_SECRET_KEY` / `PAYSTACK_PUBLIC_KEY` | Billing, customer portal | [Paystack dashboard → Settings → API Keys] | Test keys in dev; **live keys only in production env**, never on developer machines. |
| `PAYSTACK_WEBHOOK_SECRET` (if set) | Webhook signature verification | Paystack dashboard | Re-verify webhook flow after rotation. |
| `GROQ_API_KEY` | AI insights | [console.groq.com → API Keys] | |
| `ANTHROPIC_API_KEY` | AI insights (optional provider) | [console.anthropic.com] | |
| `SMTP_PASSWORD` | Outbound mail | Mail provider | |
| `SENTRY_DSN` | Error reporting (all apps) | Sentry project settings | DSN is low-sensitivity but treat as config, not code. |
| AWS credentials (cloud sync) | `cloudsync/` providers | IAM — prefer roles (IRSA/instance profile) over static keys | Never static keys in prod. |
| License RSA private key | Standalone license signing | Generated by `assetiq-standalone/scripts` | Private key never leaves the license server; only the public key ships. |

Client apps (`web`, `desktop`, `mobile`) hold **no** server secrets. Web uses an HttpOnly cookie set by the backend; mobile stores its session in expo-secure-store; desktop encrypts its session with Electron `safeStorage`.

## Rotation procedure

1. Generate/issue the new value at the source listed above.
2. Update the deployment secret store (and your local `.env` if applicable).
3. Restart the affected service; verify boot + a smoke request.
4. Revoke the old value at the source.
5. If the secret may have been exposed, record it in the incident log with date and scope.
